# Test Strategy (`TESTING.md`)

NOP's tests follow the Gherkin feature list in [features/](./features/). Test names start with the scenario ID (`NOP-CONV-010`) or the review finding they guard (`P-01`), so a failing test points at the behavior it protects. Python test methods spell the ID with underscores (`test_NOP_EXP_030_...`).

## Layers

| Layer | Tool | Where | Runs | What it covers |
| --- | --- | --- | --- | --- |
| Unit (`@unit`) | Vitest, Node | `tests/unit/` | `npm run test` | Pure logic: normalization of untrusted files, coordinate conversion, wire fan-out and IDs, wire paths and highlighting, parameter layout, ramps, code highlighting (with a time budget), embed options and snippets, downloads (mocked `fetch`), icon registry rules, stylesheet scoping, the search engine and link preview tags of the pages, JSON Schema checks of the fixtures, and a fresh export of the sample network checked against the schema and the normalizer (runs Python) |
| Component (`@component`) | Vitest, jsdom, Testing Library | `tests/component/` | `npm run test` | `HoudiniNetwork` (inspector, selection callback, keyboard flow, hotkey modes, dive and back, damaged files), error boundary reset, per-viewer fullscreen, toolbar copy feedback, embed dialog height field, the `<houdini-network>` element, a fresh export drawn by the viewer (runs Python), the Parameter Inspector on the real `parameters` and `vex_wrangles` exports (tabs, folders, every widget, ramps, code and Copy, a failed download of the inspector code) and its panel (side panel or bottom sheet, dragging, keys, remembered and blocked storage), navigation on the real `assets` export (hotkeys, zoom limits, diving in and out, history, path bar trail, remembered views, focus), view-only on the real `start_here` export (flags, delete keys, arrow keys, wire clicks, Ctrl-click, Shift-drag, form controls, a frozen document), node drawing (shapes, flags, labels, badges, connectors, icons, boxes, notes, subnet inputs), the toolbar and error states, wires (width, highlight through dots, style, dotted Copy to Points input), unique icon ids, the web component and `RemoteHoudiniNetwork` (sources, attributes, moving, cancelled downloads), reduced motion, the example page's code panel (tabs, options, escaping, Copy), the playground with and without a feedback key and its oversized file guard, the feedback form (`Playground.test.tsx`, Web3Forms mocked) |
| Browser (`@e2e`, `@a11y`, `@mobile`) | Playwright | `tests/e2e/` | `npm run test:e2e` | The built playground, the `?embed=true` page and the built web component on a hostile host page, in Chromium, Firefox, WebKit, Pixel 7, iPhone 14 and iPad; axe WCAG 2.2 AA scans; keyboard flow; touch target sizes; no sideways scrolling on phones; on-demand chunks and font files; navigation gestures (`navigation.spec.ts`), view-only drags (`viewOnly.spec.ts`), embedding (default size, fonts, the script loaded twice, embed page options, host page styles with the npm stylesheet: `embedding.spec.ts`), the overview, native fullscreen and Download JSON (`viewerChrome.spec.ts`), dialogs, names, contrast and touch (`accessibility.spec.ts`), the playground's file loading (open, drop, Ctrl+V, the Paste button with a replaced Clipboard API), load errors, a failing example, the exporter download, dialogs and the embed tip (`playground.spec.ts`) |
| Exporter (`@exporter`) | Python `unittest`, fake `hou` | `exporter/tests/` | `npm run test:exporter` | Path scrubbing table, SVG metadata removal, hide-when / disable-when rules and their cache, keyframe detection, recursion rules for every kind of asset; both shelf tools with their dialogs, clipboard, status bar and saved files (`test_exporter_entry_points.py`); selection, icons, parameter modes and layout, every item and header field, and no private text anywhere in an export (`test_exporter_integration.py`); the package zip (built with Node) and the shelf file (`test_exporter_package.py`) |

`tests/setup.ts` adds the browser APIs React Flow needs in jsdom. `tests/component/inspectorHelpers.tsx` loads the example exports, builds small documents and sets the viewer size per test (`setViewerSize`), since jsdom has no layout. `tests/component/viewerHelpers.tsx` gives nodes Houdini's 100 x 30 box so fits and frames compute real zoom levels, reads the view from React Flow's transform, and presses hotkeys. jsdom measures nodes after React Flow's start fit, so tests take their reference fit from H; the browser tests (`tests/e2e/navigation.spec.ts`, host page `navigation.html`) check the start view itself. `tests/e2e/server.mjs` serves the builds, the fixtures and the host pages in `tests/e2e/host/` on two origins (ports 4173 and 4174) so cross-site cases can be tested. Outside CI, Playwright reuses a server that is already running on port 4173 and then skips its build step, so the browser tests see whatever is in `dist/` and `dist-playground/`: run `npm run build:lib` and `npm run build` first, or stop the old server. A local `.env.local` with `VITE_WEB3FORMS_KEY` puts a working feedback form into those builds, so the playground and accessibility specs block every request to `api.web3forms.com`, and the component tests replace `fetch`.

## Fixtures

- `fixtures/examples/*-network.json`: the seven guided playground examples, real Houdini 22 exports. The tests use `start_here` (`lift_tube`, `merge1`), `vex_wrangles` (`wrangle_rings`), `for_each` (`twist_piece`, slanted wires), `parameters` (the largest file, Full Parms) `assets` (subnetwork `scene`) and `selection` (stubs: `scatter_trees`, `place_trees`, and `place_rocks` with a dotted one).
- `fixtures/edge-cases/`: small hand-written files for one behavior each (malformed items, schema 2.0.0, prototype-key names, a minimized box, out-of-order merge wires, a sticky note without background, items of different kinds sharing a name, three SideFX Labs tools for the on-demand Labs icons in `labs-tools.json`, a long node name at the right edge of the network for Fit in `long-names.json`).
- `exporter/tests/sample_network.py`: builders for fake networks, and one sample network with every item kind and a private path in every text field. `python exporter/tests/sample_network.py` prints its export; the Vitest tests read it through `tests/unit/exporterSample.ts` (set `PYTHON` if the interpreter is not `python`).

## Exporter tests in Houdini

`npm run test:exporter:houdini` (`scripts/run_houdini_exporter_tests.mjs`) finds hython (`HYTHON`, else the newest Houdini in its default folder), runs `exporter/tests/houdini_session.py` in it and then checks every export against the JSON Schema and the viewer's normalizer (`tests/unit/houdiniExportContract.test.ts`, skipped in a plain `npm test`). In real Houdini it builds a network with every item kind, a renamed and an unrenamed Transform, a wrangle, ROP Geometry Output, a subnetwork, a selection and a locked and an unlocked user asset, scrubs private paths, and exports every SOP type in full mode without an unreadable parameter. To test another installed version, set `HYTHON` to its `bin/hython` (checked with Houdini 20.5.613, 21.0.671 and 22.0.466). It needs a local Houdini and its license and takes a few minutes. Run it before committing an exporter change. It is not in CI: GitHub's runners have no Houdini, and a licensed install there needs SideFX credentials and license terms that allow automated use.

## Not automated (manual checks)

- A real Houdini session for what hython cannot do: install the package, run both shelf tools with their dialogs (`NOP-EXP-041`), check one export by hand.
- Real phones and tablets (the browser tests use device emulation): checked by hand on a physical iPhone 13 and iPad 11.
- Visual fidelity against Houdini screenshots (no screenshot comparison tests): checked by hand.

## Coverage

`npm run test:coverage` measures the Vitest layers (unit and component) only; the browser tests are not counted, so code that only runs in a real browser (the `?embed=true` page, drag and drop, pinch and two-finger pans, the example page script) shows as uncovered there. The exporter has no coverage package (standard library only); `python -m trace --count --summary --missing --module unittest discover -s exporter/tests` gives its line coverage.

## Writing a test

1. Find or add the scenario in `docs/features/`.
2. Pick the lowest layer that can show the behavior (unit before component before browser).
3. Name the test after the scenario ID and keep one behavior per test.
4. For the exporter, extend `exporter/tests/fake_hou.py` only with what the exporter calls. Its dialogs answer from `ui.answers` and fail on any dialog a test did not expect.
